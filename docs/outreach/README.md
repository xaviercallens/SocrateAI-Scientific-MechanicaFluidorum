## The standing rules for any public post about this programme

These are not style preferences. Each one is here because breaking it has cost something, in this
programme or in the sibling one.

1. **Never lead with Navier–Stokes.** There is no result on it. Our own abstract says uniformity in
   the truncation is not addressed, and that is the whole problem. A message that opens with
   Navier–Stokes progress is sorted, correctly, into a very large pile.
2. **Disclose the AI assistance in the post itself**, not only in a linked repository.
3. **Link the source.** Withholding it to seem more casual is the practice the sibling repository
   removed from its own guidance on 2026-09-18, and the reasons are written up there.
4. **Never ask a reader to run anything** in order to follow the argument.
5. **Where someone else's mathematics is correct, say so first and without hedging.**
6. **Quote no number that is not traceable to a committed artefact**, and commit the artefact.
7. **A green board is never evidence about the world.** If a post implies otherwise, it is wrong
   whatever else it says.

## What is deliberately not being pitched

The two-laboratory convergence is genuinely interesting: two efforts by the same owner, with no
shared code or method, arriving independently at the kernel gate with the same axiom footprint and
at a changelog that records corrections rather than rewriting them.

It is not in either draft, and it should not be added until the second laboratory has a verifier
who is not also its author. Its producer, verifier and sole reviewer are currently the same party,
so "independently verified" is not a description available to it, whatever the Lean says. The
kernel transcripts are now committed there, which was the first of two things standing in the way;
the second is a second person.
