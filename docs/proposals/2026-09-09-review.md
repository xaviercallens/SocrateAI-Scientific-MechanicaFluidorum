**Two independent causes**, both already on record in this repository:

1. **The retired `fin_cases` fragility was reintroduced.** The submission drops the
   `Matrix.cons_val_two / head_cons / tail_cons` family that the 2026-08-25 arbitration added
   precisely because `![1,0,0] 2` does not reduce under `norm_num` alone.
2. **`Finset.sum_ite_eq'` is called with an argument it does not take.** The active file passes
   three arguments and then discharges the membership side condition with `if_pos`; the
   submission passes the proof as a fourth argument, which is a type error, not a naming drift.

## What the submission would also have cost, even had it compiled

Statements are identical to the active file — no new mathematics is offered. What differs is
**evidence**:

- **Five theorems deleted**: `pairState_at_k0`, `pairState_at_neg`, `pairState_other`,
  `dot_k0_amp`, `dot_negk0_amp`. These are the named intermediate steps the active proofs are
  built from.
- **Four audit certificates deleted**: `#print axioms` for `pairWitness_nontrivial`,
  `leray_conj`, `leray_symm`, `leray_col_orthogonal`. Ten certificates become six. Under SPEC §5
  the footprint print *is* the Tier A gate, so removing certificates removes gate coverage —
  the one direction in which a file must never move.

master plan ("éradiquer les `sorry` résiduels dans les témoins") had no target: `grep` finds the

replaced by the eleven narrow modules the file actually uses. The umbrella forces a full Mathlib

statement and no proof changed, and the ten certificates are unchanged.
